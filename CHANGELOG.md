- **`--no-verify` / `-n` / `-c core.hooksPath=…` now denied at the PreToolUse layer (M52 F1 audit, Task 25 — Major).** Those flags skip the native hook, so a present-but-stale sentinel passed the existence-only PreToolUse check and ADR-004's tree binding was never evaluated. `hooks/lib/commit-detect.sh` gains `gf_commit_skips_hooks` and `gf_commit_overrides_hookspath` (argv-walk predicates over the committing segment — a `-m "use -n"` message body is never misread); `hooks/check-commit.sh` denies on either before the sentinel check, tier `light` still off. Known limit, stated: a commit issued from inside a script file is invisible to argv inspection by construction. Record: F1-2.
- **Eight wrapper shapes were invisible to `commit-detect.sh` — `(…)`, `$(…)`, backticks, `{ …; }`, `if`, `command`, `exec`, `time` (M52 F1 audit, Task 25 — Major).** Combined with `--no-verify` this was a full bypass. `_commit_detect_scan_segments` now pads `(`, `)`, `{`, `}` and backtick as segment boundaries (quoted message bodies still fold to one token); `_commit_detect_walk_core` strips a closed transparent-prefix set (`if elif while until ! command exec time nohup builtin $(`) before the `git` test. Found on the way: `xargs -n1` with no command runs GNU `echo`, which swallowed a bare `-n` token — the tokenizer now runs `xargs -n1 printf '%s\n'`. Cases for every shape plus message-body negatives in `tests/test-commit-detect.sh`. Record: F1-3.

- **`/g-resume` — new Step 0 syncs with origin before reading anything.** The durable record lives in git, and a fresh session on a clone that lags origin re-hydrates from a stale handoff. Step 0 is existence-gated — it never runs (and never mutates) a tree that Step 1's own stop condition would have refused. It resolves the remote from **configuration first** — `git config --get branch.<branch>.remote` — rather than from splitting `@{u}`'s printed string, which is wrong on a raw-URL remote, on a custom `remote.<name>.fetch` destination namespace, and on `branch.<name>.remote = .` (where `@{u}` prints a bare branch name with no `/` at all); splitting the printed ref at its first `/` survives only as a **documented fallback**, used when configuration gives nothing, and a leading segment that is missing or empty is reported as no remote rather than guessed. Only then does it resolve the comparison ref, before any count runs. A non-`origin` remote is fully supported (the real remote name is used in every subsequent line); detached HEAD, a missing remote and an undeterminable one are noted and skipped rather than hitting `@{u}`'s fatal error; a branch tracking the local repository (`.`) skips as `local-only remote`. When `@{u}` does not resolve, the run takes the **no-`@{u}` path** — the name matters, since the old "tracking-less" label was factually wrong on half of it — compare-only and never fast-forwarded, because the ref would be an inference rather than a declared tracking relationship, and split honestly into its two sub-cases: tracking configuration present but unresolved (blocker `upstream ref unresolved`; a ref missing after the fetch means `upstream branch gone`) versus no tracking configuration at all (blocker `no tracking configuration`, compare-only against `origin/<branch>`; a missing ref means `no upstream`). The single ref-existence test happens *after* the fetch, on both paths, so a branch pushed from another machine since this clone last fetched is still caught — only a genuinely never-pushed branch skips as `no upstream`, while a ref the fetch itself pruned away skips as `upstream branch gone`, and a repository with no commits yet skips as `unborn HEAD` rather than dying inside `rev-list`. The fetch is bounded and non-interactive (`GIT_TERMINAL_PROMPT=0` plus a 10s `timeout` cap, borrowing the `command -v timeout` guard pattern — and only that — from `hooks/session-start.sh`, whose own fetch is *backgrounded* where this one runs in the foreground; the residual is stated rather than glossed: the env var closes git's own terminal prompt, not a GUI credential helper, an SSH passphrase, or a host-key prompt, and on a system without `timeout` the fallback is bounded by nothing) because it runs at a session's first prompt; a failed fetch — timeout, credential refusal, or any other non-zero exit, all one branch — skips classification entirely: no compare against stale remote-tracking refs, and no pull at a remote just proven unreachable. What remains is a **total four-row state classification** — in sync · ahead-only · behind-only · diverged — each rendering exactly one `Freshness:` value in a new slot in the Step 3 re-entry briefing template, with ahead-only reported as unpushed local commits (a real re-entry signal, never a pull). Classification alone could still lie confidently on one axis, so a separate **`Record axis:`** briefing line was added: `Freshness:` speaks only for the current branch against its own upstream, which meant a session on a feature branch level with `origin/<feature>` read `synced` while the handoff on the mainline branch had moved on — and the fast-forward advanced only the feature branch, carrying the same stale record. New sub-step 0g resolves the record-bearing branch from one ordered candidate list — `refs/remotes/<remote>/HEAD`, then `main`, then `master`, each accepted only if `git rev-parse --verify` accepts it, with a failed candidate advancing to the next rather than ending the chain (`<remote>/HEAD` is created only by `git clone` or an explicit `git remote set-head`, and can dangle where it does exist) — counts how far behind it HEAD is, and reports that in its own line, never as a `Freshness:` variant. The line is otherwise absent only on walks that exited before classification. Totality is over the walks that reach the briefing: two terminate before it by design and render no value — the 0a existence-gate skip and the 0f decline — which is correct behaviour, not a coverage gap. The fast-forward is a **local `git merge --ff-only <ref>`**, never `git pull --ff-only`: `pull` runs its own fetch — a second unbounded, credential-capable network call at the same first prompt 0c is carefully bounded to protect — and because it re-fetches, the count it reports can be stale before it lands. 0c has already fetched and 0d has already verified the ref, so nothing remains to fetch and the reported N is exactly the count classified; the `--ff-only` guarantee is unchanged. It is an *action* on the behind-only row rather than a state of its own, gated on behind-only + clean tree (`git status --porcelain --untracked-files=no` must exit 0 **and** print nothing — a failing status is not clean, and previously read as one) + configured-upstream path + session-start invocation, with a defined failure branch whose literals name the *fast-forward* rather than a pull — `Fast-forwarded N commits — now at <short-sha>` and `stale — N behind (fast-forward failed)` — since no network call happens there and the old `(pull failed)` sent a reader hunting a credential or connectivity cause instead of the local ones (untracked-file collision, a non-fast-forwardable ref); when any gate is unmet the row reports stale-and-not-fast-forwarded naming the first blocker in priority order (working-tree state unknown / dirty tree / upstream ref unresolved / no tracking configuration / mid-session run / session phase unknown) instead of interrupting the developer. ## [2.2.1] — 2026-07-01

### Fixed

- **The commit gate now actually blocks (critical).** `hooks/check-commit.sh` used `exit 1` on every block path — but a Claude Code PreToolUse hook only blocks the tool on `exit 2` or a stdout `permissionDecision:"deny"` decision; `exit 1` is a *non-blocking* error, so the `git commit` proceeded anyway. The gate — the plugin's central promise — was a warning that let the commit through, and the unit test encoded `exit 1` as the "blocked" contract, so the suite never caught it. Every block path now goes through a `deny()` helper that emits the deny JSON on stdout **and** exits 2 (belt-and-suspenders across hook-semantics versions), with the reason on stderr for the CLI. `tests/test-check-commit.sh` now asserts real blocking (exit 2 + deny JSON) and adds a regression guard that fails on the old `exit 1`/no-JSON behaviour. - **Review pipeline no longer fails open on a security finding (Bug B).** `review-orchestrator` bucketed findings as Critical/Major/Minor and only escalated to FAIL on Critical, but `security-auditor` grades Critical/**High**/Medium/Low — a lone security **High** (auth bypass, data exposure) mapped to no bucket, so the verdict came back PASS and `code-lead` issued MERGE READY. ## [1.7.0] — 2026-06-26

### Added

- **Single-use agent doctrine (G-RULES §C)** — an agent gets one approach and one attempt; it is never continued, re-prompted, or reused for a retry. Names and prevents **context poisoning**: because a context window conditions the next token on its entire contents, a failed exploration left inside an executor degrades its output (anchoring on rejected options, hedging, clinging to wrong first guesses). Single-use agents make this structurally impossible — the failed exploration dies with the agent; only distilled learnings cross back to HQ.
- **`FAILED` agent outcome + `LEARNINGS:` field** — the agent return contract is now `RESULT: DONE | FAILED | BLOCKED`. `FAILED` = the approach didn't work; the agent returns a learnings report (approach tried, why it broke, what's ruled out, a recommended different approach) and is discarded. `BLOCKED` stays = an external dependency makes the task impossible to proceed (straight to the human; a different approach won't help).
- **`/g-execute` redeploy loop** — on `FAILED`, HQ reads the learnings (optionally via `error-detective`/`debugger` for a different mechanism), hands a **fresh** single-use agent a clean starting point (revert partial changes or describe the working-tree state), and redeploys seeded only by the distilled learnings — never the dead agent's context. Bounded by Three-Strikes: three fresh attempts with different mechanisms, model tier escalated before attempt 3, then HQ stops and escalates to the developer with the full learnings trail. Retries are logged to `.claude/escalation-log`.

### Changed

- **`A8 Three-Strikes`** reconciled with the single-use doctrine — it is now the explicit ceiling on the retry loop; each strike is a fresh agent with a different mechanism, never the same context re-poked.
- **`docs/orchestration-patterns.md`** gains a *Doctrine — single-use agents and context poisoning* section framing the rule as the automatable form of the deliberation/execution split (burn the context, keep the lesson).

Pipeline: test coverage check (offers `test-writer` if thin) → parallel pre-analysis (`code-reviewer` + `architecture-enforcer`) → `spec-writer` dispatch → human approval gate → wave execution via `refactor-executor` with Tier 1 gates between waves → `/g-review` merge gate → milestone file updated if launched from an audit milestone.

Scope is strict: stable and LTS releases only; alpha/beta/RC/canary/experimental results are ignored.
