## Patterns

### Worked well
- **Delegate yield + resume pattern:** Five separate resumes (four on Task 5 alone) all executed cleanly and produced the intended work. No context loss, no re-derivation needed. The pattern respects the contract: output_file written first, one resume per turn, HQ reads back the file before accepting DONE.
- **Off-context re-derivation for README audit:** Wave 2 audit agent (doc-reviewer) produced 44 items from first-principles greps (`README.md` line-by-line vs source claims); HQ never held the audit logic. Later fix pass (Wave 3) executed independently against that audit's findings without re-deriving.
- **Plan's forecast hit exactly:** Scenario 1 (stale carriers survive review) fired as written. The five live surfaces (`g-wiki/README.md:7`, `project_brief.md:38,:67`, `milestones/M41.md:3,:5`, `decisions/010-…:99`) were not in the changed file set — no task owned them, Task 21's literal sweep greps (`2.4.1`/`coming in 2.5`/`candidate`/`pending`) miss them. Doc-reviewer caught them at r1. This is the exact carry-forward lesson from patterns-resolve-27's "four rounds running on the same class."
- **HQ inline work for repeated delegate yields:** Task 2's ROADMAP remainder and Task 5's done-condition greps + README:300 fix were finished by HQ after the delegates stalled. Quick win, unblocks the gate.

### Avoid / do differently
- **Stale carriers reproduce exactly.** This session was built specifically to avoid them (rebuild map is the filter, plan Task 21 is the sweep), yet the forecast's #1 scenario fired in the first gate. The lesson from patterns-resolve-27 (2026-08-28) was "grep the literal fact repo-wide before each gate, not the changed-file set." This pass **did not follow it**: no pre-gate grep sweep of dropped-milestone tokens across the full repo was added to the plan before dispatch. Next time: add a mandatory grep step to every gate's setup that greps the literal facts changed by the milestone (milestone tokens, the old version string, key phrase changes) across every tracked surface, *before* running the gate. The alternative is a Task 3b/Wave 3 fix, which is what happened here.
- **Delegate yield → record-file prompt instruction:** Three doc-writers each yielded mid-task with a fragment and no RESULT block. Each had to be resumed once; the README fixer needed four. No agent dispatch prompt said "write your record file first if you're at the end of a turn." Starting assumption was "resume = pick up where you left off", but in practice it means "write the record file you didn't get to yet, then we'll talk next steps." Add that instruction to every document-writer dispatch in the plan.
- **HQ should read disk before calling FAILED.** A delegate mid-task stall (no RESULT, but also no obvious error) looks like failure until you check whether the output file was written. Disk check first, resume if present. This is already the pattern (§C), but the journal shows HQ taking 2-3 turns to discover it.
