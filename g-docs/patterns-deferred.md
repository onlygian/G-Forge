## 2026-08-15 — summary-disagrees-with-own-detail (Systemic, weighted 3)

- Sources: retros/2026-05-19-m10-m14-pre-shipping-sweep.md (:34, :35) · retros/2026-07-23-m46-update-integrity.md (:25, hit twice in one pass) · retros/2026-08-15-g-patterns-two-phase-lifecycle.md
- Proposed target: `rules/g-rules/G-documentation.md`, `### Currency rule` — a paragraph requiring derived counts and summary figures (suite totals, file/skill/agent counts, list sizes, version stamps) to be re-derived from their source of detail rather than carried forward as prose, with the detail authoritative on disagreement.
- Triage: **defer — pattern confirmed, drafted wording rejected at review.** Two defects in the draft, both worth carrying:
  1. **Wrong trigger.** The draft read "re-derived … in the same PR that changes them", binding to the restated *figure*. The mined failure is the opposite case: the PR changes the underlying detail and leaves the stale count untouched. As written the rule could not fire on the case it exists for. Bind the trigger to the source of detail changing.
  2. **One-way pointer sold as an interlock.** The draft cross-referenced G-RULES §H (which already pins the same invariant for suite totals at the gate) and instructed "keep the two in step if either is edited" — but §H carries no reciprocal pointer, so an editor working in §H gets no signal anything depends on it. Either add the back-reference or state the dependency as one-directional. Also note §G and §H are independently selectable presets: a project on the A–G preset has no §H for the pointer to resolve against, so the rule must stand alone without it.
- Placement: any future pass that authors the wording fresh. The evidence is the strongest in the corpus (3 retrospectives); only the drafting failed.

## 2026-08-15 — timing-bounds-without-platform-headroom (Systemic, weighted 3)
- **2026-08-27 update:** the narrow gap named below ("under what machine conditions") APPLIED as a refinement of the architecture note — "measured under load (an `nproc`-core busy-loop), never quiet-machine idle time alone", with the rejected quiet-machine run condition explicitly ruled out in the note itself. `tests/lib/timing-bounds.sh` already carries the loaded measurements (2026-08-21).
- Sources: retros/2026-08-12-m47-planning-honesty.md · forecasts/m47-planning-pipeline-honesty.md
- Proposed target: `profiles/claude-plugin/rules/architecture.md`, the "Note — timing assertions in hook tests" — pin the measurement basis for "worst observed".
- Triage: **defer — narrower than it first read, and the drafted wording is unsafe for consumers.**
  - **Mostly already fixed.** The 2× headroom requirement and the named-`*_MS`-constant-with-WHY requirement both pre-date this pass. The only genuine gap is that "worst observed" never said *under what machine conditions* it is measured — which is why the carried `GUARD_WINDOW_MS` question (20000ms authored against a 9.9s quiet worst, vs 24.3s observed under parallel agent load) has stayed open.
  - **Why the draft was rejected.** It made a quiet machine "the required run condition for timing suites" with no exception. That is unsatisfiable on hosted CI, containers, or any shared executor, and it collides with G-RULES §H Tier 1 (suites block every commit, any red stops the commit): on a shared runner the rule forbids widening the bound while its only escape hatch — a quiet re-run — is unavailable, leaving the developer's sole compliant move as removing timing suites from the gate, which the rule never sanctions. A rule a consumer's default setup cannot satisfy gets ignored wholesale, taking the sound 2×/named-constant part with it.
  - Both "quiet machine" and "which suites are timing suites" were also undefined anywhere in the repo, so the requirement was unenforceable as written.
- Needed for a future attempt: an operational definition of quiet, a stated set (or detection rule) for which suites the condition binds, and an evidence path that degrades gracefully on shared infrastructure.
- **Developer decision still open, unchanged by this deferral:** the `GUARD_WINDOW_MS` 20000-vs-24.3s question. The quiet-runner convention was chosen in session on 2026-08-15; it is the *rule text* that parked, not the decision.
